What it is

一个「无人值守、自主活动」的 Minecraft AI 玩家

MinePilot Forge 模组在服务端内建一个无账户 headless ServerPlayer（叫 MCAI）—— 不需要图形客户端、不需要真人常驻。它自己在世界里跑、砍树、合成、战斗、退避。 而本仓库解决的是它落地到真实网关时暴露出来的一连串问题。

闭环

MCAI 在线 → 收到目标 → LLM 决策 → 执行技能（移动/砍树/合成/放置）→ 服务端校验完成

最通用的一条

「输出契约降级」+「无 schema 契约内联决策 schema」对 任何 不严格支持 json_schema 的 OSS / 本地 / 第三方网关都通用。

Our improvements

对上游 MinePilot 的 8 个补丁改进

按「解决的因果链」分四组，每条都对应一个线上真实故障。 这是本仓库对 GitHub 用户最有价值的部分。

A

输出契约降级 —— 让「弱 provider」也能用

2 commits

修复 capability 拒绝识别 4fcbd35

问题

ProviderErrorClassifier 在「provider 拒绝能力时若没带 param 字段」就判定失败。 原 mentionsField 是大小写敏感且要求非标识符边界，json_schema 对不上消息里的「JSON schema」，导致拒绝永远无法被识别。

ProviderErrorClassifier.java

探测被拒时继续协商更弱契约 bfe8833

问题

JdkProviderCapabilityProbe 探测到输出契约被拒时整体终止， 直接变成 startup_model_unavailable_invalid_request —— bot「身体在、无大脑」。

改法

不再终止，而是 break 继续试下一个更弱的契约： JSON_SCHEMA → JSON_OBJECT → PLAIN_JSON → PLAIN，全部失败才算 failed。

净效果：能协商降级到 RESPONSES/JSON_OBJECT 契约 → ready=true
JdkProviderCapabilityProbe.java
B

无 schema 契约也把决策 schema 喂给模型

1 commit · 最关键

内联决策 schema 进 instructions d5eefe6

问题

JSON_OBJECT / PLAIN_JSON 契约原本根本不会把 schema 发给模型 （只有 JSON_SCHEMA / FORCED_FUNCTION 会）。模型连字段名都不知道，只能瞎猜 → 每次 MALFORMED_RESPONSE / missing_fields → SAFE_IDLE。 这才是「目标被接受却立刻不执行」的真根因。

改法

ModelRequestFactory 新增 contractInstruction()：当契约是 JSON_OBJECT / PLAIN_JSON 时，把 codec.schema(context) （含当次可用 skill 枚举）序列化内联进 instructions；Responses 与 Chat Completions 两条线都改。

净效果：Live-model accepted decision → bot 真的完成 gather_nearby_wood 拿到木头 → 端到端首个自主闭环跑通
ModelRequestFactory.java
C

决策质量 + 技能失败诊断

4 commits

技能失败码落日志 0435140

问题

失败只有一个笼统结果，拿不到真实原因。

改法

BrainOrchestrator 把 SkillFailure.code 落日志（挂在 -Dmcai.liveModelTest=true 诊断开关下）。

净效果：拿到真实失败码 use_block.action_target_occluded，成为下面两条的修复依据
BrainOrchestrator.java

use_block 前置 equip_item + 同面 look_at f482154 d8a81b8

根因

isBlockUnderCrosshair() 用 getViewVector 做 raycast， 命中点必须落在 target.hitPoint() 0.5 格内且 face 完全一致， 否则报 action_target_occluded。

改法

FairInteractionSkills 的指南要求先 equip_item， 且明确「只作用于准星下那个面，必须先 look_at 同一方块面再 use_block」。

FairInteractionSkills.java

技能指南压回 14000 字符硬上限 233fc67

问题

D

真人陪玩不被误踢（明确的上游 bug）

1 commit

名字规则不再校验真人玩家 04770b4

问题

MinePilot 的名字规则 [A-Za-z0-9_]{3,16} 把每个真人玩家名也拿去校验， 且登录监听器跑在 PlayerList#placeNewPlayer 内部 → 2 字符的名字（如 DC） 一进服抛 name_too_short → 被 PrepareSpawnTask 捕获 → 客户端只看到笼统的 Invalid player data。

改法

CompanionWorldData.rememberPlayerName() 校验不过就静默 return（不再抛）， 登录监听器整体包 try/catch (RuntimeException)。 版本串故意不改 → 客户端无需换 jar。

净效果：2 字符名真人玩家进服成功，不再被误踢
ModelSetupModule.java · CompanionWorldData.java
The panel

从零自研的 Web 配置面板

源码里 grep -rn "HttpServer\|WebSocket\|text/html\|/api/" 只命中一个回环 MCP —— 上游模组本身没有任何 Web 面板。所以我们已经从零新建并部署了一个： 容器 mcai-panel，端口 25800，零依赖。

模型连接

baseUrl / name / soft / hard —— 模型地址、模型名、软硬超时。

API Key

写 secrets/mcai-api-key，只写不回显，页面只显示字节数 / 字符数 / 权限位。

MCP 控制口

mcpEnabled / mcpPort —— 是否开 MCP、监听端口。

权限白名单

chatAllowed / waypointAllowed，UUID 列表，逗号分隔。

皮肤

skinAuto 自动导入 config/mcai-companion/skin.png；CLASSIC / SLIM。

动作按钮

保存并重启（推荐）（停止→写→启动，故意顺序，Forge 退出会刷回旧值）、仅保存、仅重启、停止/启动、测试模型连接。长任务走后台 job，一次一个。

  • 66 个属性分 5 组渲染，每个都是带类型的控件（布尔 / 枚举 / 数字 / 文本）
  • 🔒 徽标 = compose 接管键（7 个）：容器每次启动会用环境变量覆盖 properties
  • 改接管键必须勾「同步到 compose」，面板同时改 properties 和 compose；不勾会被后端拒绝
  • 或点「交给 properties 管」，把 compose 那个环境变量注释掉
  • 密钥键不回显：rcon.password 显示 •••••••• 且禁用，改密走 ⑤ 页
  • 底部：保存属性并重启 / 仅保存属性（+ 同步 compose 复选框）

天气

晴 / 雨 / 雷（可带秒数）。RCON 实时，无需重启。

时间

day / noon / night / midnight / 自定义 tick / 冻结与恢复。

游戏模式

选在线玩家一键切换（生存 / 创造 / 冒险 / 旁观）。

难度

peaceful / easy / normal / hard。

广播

向全服玩家发消息（MC 原生 say，会出现在聊天与玩家聊天栏）。

44 条 gamerule

中文标签，按天气/生存/刷怪/掉落/命令/提示/性能分组，打开即批量拉取当前值，改动点「应用」即时生效。⚠️ MC 26.2 规则名全 snake_case：keep_inventory / mob_griefing / random_tick_speed / advance_weather。

为什么没有「任意命令输入框」

面板挂了 docker.sock，不能被当成通用 shell。所有操作都走服务端白名单 buildRconCommand()（weather / time / timeFreeze / gamerule / gamemode / defaultgamemode / difficulty / say / op / deop / pardon / kick / ban / whitelist / whitelistToggle / banlist / query），参数逐项正则校验防注入。

在线玩家

实时列出用户名 + UUID（来自 /list uuids），并自动区分 AI bot（MCAI，UUID 与离线算法不符 = mod 自建无头玩家）与 真人（离线 UUID 算法匹配）。点击可复制 UUID；每行可切换模式 / 授予 OP / 踢出。

OP 列表

op / deop，即时生效，无需重启，并写入 ops.json。

白名单

实时 whitelist list，可 add / remove / 一键开关（white-list）。开关会同时改写 server.properties 并热加载。

封禁

ban（带理由）/ pardon，可看当前封禁名单，写入 banned-players.json。

面板令牌

改密 / 随机生成 48 位。改动即时生效，并同步写 compose 的 PANEL_TOKEN。

RCON 密码

改密 / 随机生成 24 位。同步写 server.properties + compose 的 mc-server.RCON_PASSWORD 与 mcai-panel.MC_RCON_PASSWORD 三处。

密钥一律不回显

页面只显示 •••••••• 与长度，前端 input 一律 disabled。

为什么改密要重启

RCON 密码进了 compose 环境变量，改完需在宿主机执行 docker compose up -d mc-server mcai-panel。面板令牌立即生效。

容器日志尾部

直连 Docker Engine API 的 /containers/<name>/logs，带 tty 的容器是裸文本、不带 tty 的是 8 字节帧头的流 —— demuxLogs() 两种都处理。

关键词过滤

去 ANSI 颜色 / 进度覆盖残留，方便在「服务器启动崩溃循环」这类噪音里捞根因。

零依赖

只用 node:http/https/fs/path/net/crypto，镜像直接复用 node:22-alpine，不需要 npm install，构建秒级。

就地改写，保留注释

setTomlValues() / setProps() 只替换目标键那一行，保留全部注释和排版；缺键插到对应头之后。不引第三方库 → 不把用户的注释吃掉。

RCON 自己实现

不引库。认证要等到 type=2；响应 150ms 静默即认为结束（RCON 无结束标记）；rconBulk 单连接顺序跑 N 条命令，44 条 gamerule 约 6.7s。

CRLF 解析陷阱

JS 正则 . 不匹配 \r，(.*)$ 在 CRLF 文件上整行失配且静默返回 null。所有文件切行都走 splitLines()，保证 NAS 上 CRLF 的 compose / properties / toml 都能正确解析。

定长比较防侧信道

鉴权用 crypto.timingSafeEqual 做定长比较，避免时序侧信道。

191 项自测

node mcai-panel/selftest.js（需要 Node 22）。覆盖 TOML/properties 解析、注释保留、compose env 识别、离线 UUID 算法、命令白名单注入拒绝、CRLF 回归、掩码不泄露等。

Security

安全边界：说清楚风险，才敢交出去

这个面板挂了 docker.sock，等于给了宿主 Docker 控制权。 所以它只在内网用，并且刻意不提供任意命令入口。

风险说明缓解
docker.sock 等于把宿主 Docker 控制权给了这个容器。面板被攻破 → 可控制宿主机上所有容器。 面板只在内网；令牌 48 字符随机；token 走 header，不进 URL 日志（除非用 ?token= 分享）。
能 stop/start 这是刻意设计（配置要重启才生效），但也意味着误点会踢掉所有玩家。 长任务串行 + 进度可见；「停止」是独立按钮，不藏在保存里。
RCON 面板 若开放了任意命令 = 远程 Root。 没有任意命令入口，只有白名单动作 + 参数正则校验。
HTTP 明文 内网明文传输，令牌在链路上可见。 若要出公网，必须套 Nginx/Caddy + TLS + 额外认证。25800 不要直接暴露到公网。
写 api-key API Key 落到宿主机文件。 权限强制 0600、属主 1000:1000；校验长度 ≥8、拒换行。

回滚方式

docker compose rm -sf mcai-panel 即可摘掉面板，mc-server 完全不受影响 —— 面板是旁路，不碰 MC 进程。

Getting started

把它跑起来

克隆仓库，把 mcai-panel 代码放进你的 compose 目录，加一段服务块即可。

bash — deploy
# 1. 克隆（含面板代码 / 文档 / compose 示例 / 验证脚本）
git clone https://github.com/DC1024/minepilot-panel.git
cd minepilot-panel

# 2. 生成一个面板令牌（48 位，别用示例值）
python gen_token.py            # 或 node -e "..."

# 3. 在 compose 项目目录里加入 mcai-panel 服务
#    参考 docker-compose.example.yml（凭据已脱敏）
cd <你的 compose 目录>

# 4. 首次起面板
docker compose up -d mcai-panel

# 5. 打开 http://<SERVER_IP>:25800 ，粘入面板令牌

# 改了 server.js / index.html 之后：只读挂载，Node 不热重载，必须重启
docker restart mcai-panel

# 自测（需要 Node 22）
node mcai-panel/selftest.js    # 191 项断言
面板是旁路，先跑通 MC 再装它

面板只读写 server.properties / mcai-companion.toml / secrets/mcai-api-key，并通过 RCON 和 docker.sock 操作容器。MC 本身跑不起来时，面板也帮不上忙。

改 AI 配置走「保存并重启」

toml 是 ForgeConfigSpec，启动只读一次，不支持热改；而且 Forge 正常退出会把旧值刷回去，所以面板故意用「停止 → 写 → 启动」的顺序。

接管键要勾「同步到 compose」

7 个键（MODE / ONLINE_MODE / WHITELIST_PROP / DIFFICULTY / ENABLE_RCON / SIMULATION_DISTANCE / VIEW_DISTANCE / RCON_PASSWORD）由 compose 环境变量接管，容器每次启动会覆盖 properties。只改 properties 会在下次启动被打回。

想看 AI 的决策细节，开诊断开关

JVM_OPTS: "-Dmcai.liveModelTest=true" 会打印 Live-model decision rejected: kind=..., message=... 与 Live-model skill failed: skill=..., code=... —— 这是唯一能看到 ModelFailure / SkillFailure 细节的途径。

上游项目

MinePilot（weidakuang/MinePilot，mod id mcai_companion，LGPL-3.0）。本仓库的改动基于它，构建 workflow 在 DC1024/minepilot-build。

客户端的坑

服务端是 Forge，不是原版。客户端必须装同名同版本的 jar（MATCH_VERSION 精确匹配），并且 Java 要 25、MC 要 26.2、Forge 要 65.0.0。

离线服的限制

online-mode=false 时游戏内「设置 AI」界面永久不可用（hasSecureTransport 要求 pipeline 有 decrypt+encrypt）→ 改模型走 toml。想让别人在聊天里指挥 AI，给 OP 或把 UUID 加进 [chat] allowedSenders。
